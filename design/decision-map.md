# ALA 品牌治理看板｜三方对应与最终结构

## 1. 三份输入各自代表什么

### 芬芬姐的 HTML：产品基础，必须保留

- 按实际部门拆分：品牌／公关、产品及运营、投放广告、客服与消保、催收／贷后、风控、法务合规、数据治理／PMO。
- 部门入口直接可见，不要求老板先理解四大治理板块。
- 本周汇报采用直观表格，能看到事项、产出、负责人和进度。
- 每个部门保留自己的指标、工作计划和工作包全景，不强制套同一里程碑。
- 首页可汇总各部门工作包，第一次向老板介绍整体工作时使用。
- 适配笔记本电脑，不能把字和信息压得太小。

### 李阳的 5 张看板图：结构借鉴，不是页面基础

吸收：

- “治理汇报第 N 周”的累计周期概念。
- 日期、更新时间、项目健康状态。
- 整体完成进度。
- 全景图、指标、周进展之间的清晰层级。
- 向老板解释项目时先建立全局认知的思路。

不照搬：

- 不把“品牌建设增长／用户保护／风险保障／数据与治理决策”直接做成一级业务导航。
- 不把多个部门揉进一个大模块，否则指标、责任和周汇报无法对应实际部门。
- 不照搬统一的三季度里程碑；当前各部门没有同一套真实里程碑。
- 不照搬“完成情况／本周成果／问题风险／解决方案／下一步”五块重复展开的周进展结构。

### 会议记录与聊天截图：最终决策

- 七类信息都要有，问题不是删掉，而是确定高低频和前后顺序。
- 首页是 PMO 每周向老板汇报的目录，不是每周重复讲完整总览。
- 首页先回答：第几周、整体进度、本周谁汇报、汇报什么。
- 首页本周目录只保留：部门、汇报事项、进度、第一负责人；协作方与详细时间进入详情。
- 指标如保留，只显示目标、当前值、较上周变化，不放原因和公式。
- 部门页先讲本周，再讲指标；长期工作计划和工作全景放后面。
- 第一次介绍时需要工作全景，日常周会不要求老板每周重看。

## 3. 最终页面顺序

### 汇报首页（高频）

1. 治理汇报第 N 周、日期、更新时间、健康状态、整体完成进度。
2. 本周汇报目录：本周实际汇报的部门、事项、进度、第一负责人。
3. 核心指标快照：目标、当前值、较上周变化。
4. 工作总览入口：八部门、工作包和任务总量；完整内容放到“工作总览”。

### 部门页（高频在前，低频在后）

1. 部门页头：所属治理板块标签、汇报周次、部门总体进度、第一负责人。
2. 本周汇报：事项、明确产出、进度、第一负责人。
3. 部门核心指标：目标、当前值、较上周变化。
4. 部门工作计划：沿用部门自己的月份与阶段安排。
5. 部门工作全景：工作包、任务、负责人、状态和协作关系。

### 工作总览（低频）

- 汇总八个实际部门的工作包和任务。
- 用于第一次给老板讲整体治理范围，或工作结构发生变化时复核。
- 不进入每周首屏，也不要求 PMO 每周重复维护一份四大模块镜像。

## 4. 验收标准

- 1366×768 首屏必须看到第几周、整体进度、健康状态和本周汇报目录。
- 首页默认只展示当周需要汇报的部门，不强行展示全部八个部门。
- 八个部门仍可从顶部直接进入。
- 点击首页汇报部门能进入对应部门页，点击事项能查看详细产出与协作信息。
- 部门页本周汇报必须位于指标和工作计划之前。
- 不出现虚构的统一里程碑。
